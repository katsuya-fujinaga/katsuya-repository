# MD → スライド変換

既存のナレッジノート・文書MDを、単体HTMLビューア（viewer.html）用のプレゼンMDに変換するワークフロー。

> **セットアップ**: このフォルダを `~/.claude/skills/md-to-slides/`（Windows: `C:\Users\<ユーザー名>\.claude\skills\md-to-slides\`）に置き、Claude Code を再起動する。

## ワークフロー

### 1. 元MDを読んで構造を把握

- 見出し構成、要点の数、具体例の有無を確認
- スライド枚数の目安: 元MDの `##` 見出し数 × 1.5〜2倍

### 2. スライド構成を設計

典型的な構成パターン:

| スライド | 内容 |
|---------|------|
| 表紙 | `#` タイトル（複数行見出し可） |
| 結論/メッセージ | 最も伝えたいことを先に |
| 背景/問題提起 | なぜこの話が必要か |
| 本編（複数枚） | テクニック・手順・事例を1枚1テーマ |
| まとめ/一覧 | グリッドで俯瞰 |
| 適用例 | Before/After の2列対比 |
| 締め | 行動を促す1メッセージ |

ユーザーに構成案を提示して承認を取ってから執筆に入る。

### 3. テーマは書かない（front matter に `theme:` を入れない）

**front matter に `theme:` 行を入れないこと。** テーマは閲覧時に viewer.html 側で選ぶもので、選択は localStorage に保存され次回以降も維持される。執筆時にテーマを決める必要はなく、ユーザーに確認する必要もない（55種のテーマ名を覚えているユーザーはいない）。

`theme:` を書くと、viewer.html のテーマ選択が「mdの指定のまま」の状態のときにその指定が効いてしまい、「選んだはずのテーマにならない」原因になる。ユーザーから明示的に「このテーマで固定して」と指定された場合だけ書く。

注: 色指定はプリセット色（`red` / `yellow` など）を使う。テーマ固有の色名はテーマ切替時に解決できなくなる場合がある。

### 4. イラストを調達（任意。デフォルトは画像なし）

**このスキルは素材サイトを事前に指定しない。** どのサイトから画像を取るか、そこから自動ダウンロードしてよいかの判断は、必ずユーザーが行う。

手順:

1. 画像を入れるかユーザーに尋ねる。不要ならこのステップを飛ばす
2. 入れる場合、**ユーザーに素材サイトを尋ねる**（URLまたはサイト名）
3. そのサイトの利用規約・robots.txt を確認してよいか**ユーザーに承認を取る**（確認自体がサイトへのアクセスになるため）
4. 承認後、規約を確認して要点をユーザーに提示する（商用利用の可否、帰属表示の要否、自動アクセスの制限）。**自動ダウンロードしてよいかの最終判断はユーザーが行う。Claudeが独断で決めない**
5. ユーザーが承認したら: ブラウザでキーワード検索 → 画像要素の src を取得 → ダウンロード（サイトのHTML構造はその場で読む。決め打ちしない）
6. ユーザーが「自分で手動DLする」を選んだ場合は、保存先と参照記法だけ案内して待つ

配置ルール:

- 保存先: スライドMDと同階層の `img/` フォルダ
- 参照: `![alt](img/filename.png)` （リッチ系テーマは右下に自動配置）
- 枚数目安: 全スライドの 1/3〜1/2 に1枚ずつ。要所に絞る
- 帰属表示が必要なサイトの素材を使った場合は、最終スライドかフッターにクレジットを入れる

### 5. スライドMDを書く

**コンテンツ変換の原則:**

- 段落 → 箇条書き（1項目1行、体言止めか短文）
- 太字で**キーワード**を強調（1スライド2〜3箇所まで）
- 長い説明 → 削るか2枚に分割（1スライド = 1メッセージ）
- 具体例は `###` グリッドで×/○の対比にすると伝わりやすい
- 出典・研究名は残す（権威付け）が、詳細は省く

### 6. プレビューで確認

viewer.html をブラウザで開いて読み込む（Node・サーバ不要の単体HTML）。

- ツールバーの **「📄 mdを開く」**（md単体）／ **「📁 フォルダごと開く」**（画像込みで開く）ボタン
- または md・フォルダを画面にドラッグ&ドロップ
- テーマはツールバー右の **テーマ選択ドロップダウン** で即切替

確認ポイント:
- 画像が表示されているか
- グリッドの列数が意図通りか
- テキストがはみ出していないか（はみ出した場合のみ、箇条書きは7項目以上・帯リストは5項目以上で自動2列化。収まっていれば1列のまま）

### 7. 相互リンク

- スライドMDの front matter に `source: 元MDへの相対パス` を1行入れる（viewer は未知キーを無視するため表示に影響しない）
- 元MDに `> 派生：[プレゼンスライド版](相対パス)` を追記
- 追記後、元MDをgrepで読み直して「派生：」行が実在することを確認してから完了報告する

## スライド記法チートシート

以下はよく使う記法の早見表。

```
# タイトル           → 表紙（複数行: 次行を行頭スペースで）
# テキスト(2個目以降) → 中央に大きく表示
#（単独行）          → 大きな吹き出し（# 単独 + ::: speech で中央に大きな吹き出し）
## ページタイトル     → スライド区切り
### カード見出し      → グリッドアイテム（2個=2列, 3個=3列, 4個=2×2, 6個=3×2）
### 見出し＋次行本文  → カード内に説明文を入れる
<!-- 4 -->           → 横4列を強制
<!-- 2x3 -->         → 2列3行を強制
---                  → 以降をカード外へ（結論・画像をグリッドの外に出す）
::: speech / :::     → 吹き出し（囲んだ本文が吹き出しに）
1. 上段|下段          → 帯リスト（|で上段小・下段大の2段、番号は自動連番）
**太字** __下線__ *斜体* `code`  → 文字装飾
{red:文字} {bg:yellow:文字}       → 文字色 / 背景ハイライト
### ::icon:: 見出し   → アイコン付き（全43種・これ以外の名前は無効: check/x/star/heart/arrow-right/arrow-left/arrow-up/arrow-down/lightbulb/target/users/clock/chart-bar/trend-up/trend-down/shield/bolt/globe/message/mail/user/tag/map-pin/megaphone/package/key/award/message-circle/clipboard/search/compass/eye/swords/gift/flame/crown/edit/mic/map/book/door/rocket）
::arrow-down::       → 単体の矢印
![alt](path)         → 画像（リッチ系テーマは右下自動配置）
<!-- bg: #hex -->    → そのスライドの背景色を上書き
<!-- bg-image: path --> / <!-- bg-overlay: 0.5 -->  → 背景画像＋暗さ
```

front matter（`theme:` は書かない。テーマは閲覧時にviewer.htmlで選ぶ）:
```yaml
---
footer: フッターテキスト
accent: "#色コード"
---
```

## 出力ファイル構成

元MDと同じフォルダの直下に作る（ユーザーが別の場所を指定した場合はそちら）:

```
<タスク名>_slides/
  <タスク名>_slides.md    # プレゼンMD
  img/                    # イラスト（あれば）
    illustration1.png
    illustration2.png
```

viewer.html を開き、このフォルダを「📁 フォルダごと開く」ボタン（または画面にドラッグ&ドロップ）で読み込む。
